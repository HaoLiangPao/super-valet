# ADR-0002: 把推荐问题建模为 Multi-Armed Bandit

## 背景 / Context

单用户（或小圈子）自用、餐厅池 20–100 家、反馈极度稀疏。没有其他用户
的数据可借，协同过滤和深度模型在结构上就不成立。同时产品要求
「既吃爱吃的、又不能老吃同一家」—— 即探索/利用平衡本身就是需求。

## 决策 / Decision

**我们决定把「今天吃什么」建模为多臂老虎机问题**：每家餐厅是一个臂，
每次推荐是一次拉臂，用户反馈是奖励；演进路线 V0（加权随机 + 冷却）→
V1（Thompson Sampling）→ V2（contextual）→ V3（LLM 重排），
从第一天起完整记录每次决策的上下文快照（`rolls` 表）。

## 理由 / Rationale

- Bandit 是唯一与「单用户 + 小池子 + 序贯决策」结构匹配的框架。
- Thompson Sampling 的 (α, β) 表示极简、可解释、冷启动自然。
- 探索/利用平衡直接对应产品的核心矛盾（爱吃的 vs 不重样）。

## 备选 / Options considered

| 选项 | 优点 | 缺点 | 结论 |
| ---- | ---- | ---- | ---- |
| 协同过滤 | 工业界成熟 | 没有其他用户，冷启动即死 | ❌ |
| 内容/深度模型 | 天花板高 | 几百条样本喂不饱，不可解释 | ❌ |
| 纯随机 + 规则 | 零成本 | 无法吸收任何反馈 | 作为 V0 的骨架保留 |
| Bandit（本决策） | 结构匹配、可增量演进 | 收敛速度受样本预算硬限制 | ✅ |

## 后果 / Consequences

**得到**
- 一条可以增量演进、每一步可回退的算法路线。
- `rolls` 快照使未来任何算法都能离线回放对比。

**付出 / 接受的代价**
- 单店级后验在现实样本量下近似不收敛（见 research/0001 §1）——
  V1 的诚实定位是「有原则的随机化」，学习主要发生在菜系层。
- 版本间效果差异短期不可检测，不能靠线上指标驱动算法迭代。

**什么情况下应该重新考虑这个决定**
- 变成多用户产品（协同信号出现）。
- 决策频率提升一个数量级（如扩展到三餐 + 多人）。
